
## Book Contract

### Core Premise
An in-depth technical reference guide to modern distributed systems architecture, focusing on scalability, fault tolerance, and cloud-native design patterns.

### World/Genre/Tone
- **Subject**: Computer Science, Systems Engineering.
- **Genre**: Technical Reference / Textbook.
- **Tone**: Precise, instructional, and pragmatic. Dense with information.

### Structure & Voice
- **Voice**: Senior Engineer / Architect (dry, accuracy-focused).
- **Tense**: Present.
- **POV**: Second-person ("You should configure...") or Impersonal ("The system requires...").

### Main Throughline (Key Modules)
1.  **Distributed Consensus**: Paxos, Raft, and the CAP theorem deep dive.
2.  **Event-Driven Architectures**: Message queues, stream processing, and event consistency.
3.  **Container Orchestration**: Interior workings of schedulers, networking, and service mesh.
4.  **Database Internals**: LSM trees, B-trees, sharding strategies, and replication lag.
5.  **Observability & Reliability**: Distributed tracing, chaos engineering, and SLO definition.

### Progression Guardrails
- **Avoid Repetition**: Definitions are stated once. Subsequent usage assumes knowledge.
- **Pacing**: High information density. Systematic breakdown of components.
- **Texture**: Code snippets (pseudo-code or go/python), configuration examples, and architectural diagrams (described).

### Output Rules
- **Pure prose only**: Limit bullet points to necessary technical lists. No markdown check-boxes.
- **Heading consistency**: `Section X.Y: Title`.
- **Continuity**: Use terminology consistent with earlier definitions.
- **No scaffolding**: No "In conclusion" summaries unless ending a major section.

### Next Chunk Reminder Template
1.  A new technical component or pattern (progression).
2.  Interaction with a previously defined component (system integration).
3.  A specific implementation detail or edge case (depth).
4.  Best practices or common pitfalls (utility).
